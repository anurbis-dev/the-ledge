# Context map — the LEDGE

Пиксельный платформер 320×180, тайл 16px. Канон: `tmp/ledge-v19.html`.

## Точки входа

- `index.html` — DOM (`#view` + canvas `#c` мир / `#h` HUD, меню, стик, кнопки, редактор)
- `src/main.js` — bootstrap
- `src/core/game.js` — фасад симуляции (бывший IIFE `GAME`)
- `src/app/loop.js` — rAF, пауза, меню; follow камеры зовёт `followCam`
- `src/render/camera.js` — `clampCam` / `resetCam` / `followCam` / `pushCamRender` / `popCamRender` / `applyCamPan` / `clearCamPan`
- `src/ui/menu.js` — главное меню «Уступ» (New Game / Continue / Settings / Credits); список уровней — под Continue; заставка `src/ui/splash.js` зовёт `showMenu()`, не старый список

## Ядро

| Модуль | Суть |
|--------|------|
| `core/constants.js` | `T=16`, ids тайлов, физика `C` |
| `core/runtime.js` | `MAP_W/H`, `base` Uint8Array, `vary` Uint8Array, `LV`, `W` |
| `core/map.js` | запросы тайлов, скосы (`SLOPE_SPEC`: 45°, 2:1, 4:1, дуги; `slopeSpec` зеркалит H и для built-in id через `fl&1`), `rectFree`/`tileBlocks` (потолочный V-флип скоса блокирует AABB как обычный блок) |
| `core/player.js` | хват кромки, лаз, лестницы, перекладины, вода (`inWater`/`wading`/`wasWet`/`rippleT`); ступень +1 тайл — `tryMantle` только вперёд+↑; `groundSurfaceUnder` — 3-probe с fallback на `groundYAt` для плоских тайлов |
| `core/step.js` | один тик мира; вода: `wetContact` splash; на скосе `dx` режется на `SLOPE_ALONG/√2` (~90% бега вдоль склона); onGround Y-snap: `groundSurfaceUnder` вместо `slopeUnder`; декремент `digT`/`digCd` каждый кадр |
| `core/tileset.js` | дефиниции кастом-тайлов (id 64–255); новое поле `durability` в whitelist `normalizeTile()` (default 0 = неразрушаемый), перечисляется в `addTile()` (раньше терялось при создании); экспорт `tileDurability(id)` — встроенные тайлы всегда неразрушаемы |
| `core/objectset.js` | кастомные объекты-шаблоны (kind + параметры); `BAKED.objects` + миграционный мостик старого localStorage-ключа; `boot()` загружает из `BAKED` первым, потом fallback на combined ключ один раз при пустом `BAKED` (pre-fix снимок) |
| `core/object-anchors.js` | якоря (origin/grab/weapon/box) для каждого kind объекта; `BAKED.objectAnchors` + тот же миграционный паттерн; `snapshotObjectAnchors()` в bake-client.js |
| `core/runtime.js` (маунт) | новое поле `runtime.mountSkin` (геттер/сеттер оверлей) — оверрайд скина игрока поверх `LV.spawn`, временный (не персистится); управляется entities/vehicles.js при посадке/спуске |
| `levels/` | 5 карт, `build()` пишет в `base` |
| `entities/` | mk/step врагов, лифтов (`lifts.js`), платформ (`plats.js`), факелов, сундуков, щупалец, канатов (`ropes.js`), FX-эмиттеров (`emitters.js` → `S.emitters` / `LV.emitters`), NPC; копание киркой и урон-от-движения (`mining.js`, `tryDig` кнопочное, `stepContactDamage` автоматический на ходу — оба двигают `S.digHp[mapIx]` по `durability`, уничтожают в `S.gone`); **транспорт** (`vehicles.js`, `LV.vehicles: [{col,row,spriteId,objectKind,dmg?,speedMul?,jumpMul?,wallSlideMul?}]`, посадка/спуск меняет runtime.mountSkin, не персистящийся оверлей скина-физики) |
| `entities/ids.js` | `findById` / `allocId` — двери и объекты по id, не по индексу |

Двери: `pair` / `doorId` / `warp.to` — это `id`, не индекс массива. Поля `need` (bag kind|null), `consume`, `locked=!!need`; редактор ставит пару за 2 клика (`mkDoorAt`). Факел в руке — `p.torch` = id.

Выходы уровня: `LV.exits: [{id,x,y,toId}]` (миграция с одиночного `LV.exit`; blank → `[]`). `tryExit` читает exits; `finishLevel` резолвит `warp.toId` → индекс `LEVELS` (`null`/не найден → MENU, `next: -1`). Финиш рисует outro со статистикой (складка из героини): REPLAY / CONTINUE. Заставка с названием уровня — та же складка, тап/пробел сворачивает.

Зум камеры уровня: `LV.camZoom` (число, percent, дефолт 100 когда отсутствует/falsy). Значение: насколько крупно рисуются мировые пиксели на экране. <100% = видно больше мира (меньше пиксели), >100% = видно меньше (крупнее пиксели). Диапазон в редакторе: 25–400%, шаг 5. Действует только в геймплее (`ED.on` false); редактор всегда держит фиксированные 320×180 (свой зум через Ctrl+RMB/`viewScale`).

Вода (`step.js`): `wading` = ноги/центр в воде, стоя на дне у поверхности; `inWater` = плавание (центр мокрый, не wading). Splash enter/exit: `wetContact = inWater || wading` → `wasWet` / event `splash` (не только swim). `wetFeet` учитывается в shallow. Прыжок с поверхности: `swimLaunch` только вверх; на входе/возврате — короткий нырок, потом быстрое всплытие (`SWIM_UP` сильнее `SWIM_DN`). Удержание вниз ныряет медленно. Гребок вверх не режется потолком скорости. В воде `apexY` не копится — всплытие не даёт урон как с падения. С поверхности к сухому берегу + направление — `tryClimbOut` (лаз или хват); под водой, по подводным полкам и у потолка (камни сразу над водой) не вылазиваемся — всплыли у потолка, там и остаёмся. Рыбы (`stepWater` в `fx.js`) пугаются при `inWater || wading`.

Посадка в транспорт (mount/dismount): плейсбл объект уровня Vehicle (entities/vehicles.js, редактор). Механика — runtime-подмена скина игрока (skin-swap оверлей, не отдельная физическая сущность); физика/прыжок/атака/спец-действия игрока не меняются, меняется только визуальный скин (spriteId/objectKind через runtime.mountSkin) и пара стат-оверрайдов (dmg, speedMul, jumpMul, wallSlideMul). Поля player: `p.mount` (текущий vehicle), `p.mountSaved` (сохранённый spawn для возврата), `p.turning`/`p.turnT`/`p.turnScrub`/`p.turnLastDir` (разворот вместо мгновенного флипа, см. ниже). Действие (Act/Space): если за рулём — высаживает (tryDismount); иначе если рядом запаркованный (v.parked) в зоне ACT_R — сажает (tryMount, высший приоритет перед подбором предметов). Посадка недоступна с факелом в руке (p.torch≥0). Транспорт статичен пока не сел водитель (parked=true); при спуске паркуется в текущей позиции игрока. Контактный урон (см. ниже) может быть через dmg транспорта. **Аним-вокабуляр транспорта** (core/spriteset.js, vehicle-шаблон): idle/idleOff/move/**turn**/jump/fall/land/attack/**block**/**action1**/**action2**/mount/unmount (action1/action2 — слоты анимации, геймплей ещё не привязан). **Стойка за рулём** (core/step.js): присед/лёжа доступны только если у скина есть такие кадры (гейт: `hasAnim(activeHeroId(), 'crouch'/'prone')`); если 'crouch' нет, но есть 'block' — ↓ вместо приседа выставляет `p.mountBlocking` (чисто поза на кадр, физика стойки/хитбокс не трогаются, `render/hero.js:vehicleMoveAnim` рисует 'block'); нет ни того ни другого — ↓-ввод и физика стойки игнорируются, стойка остаётся 0 (стоя). **Разворот** (entities/vehicles.js:stepMountTurn): смена направления вместо мгновенного флипа — если у скина есть 'turn' anim, триггер — САМА смена желаемого направления (edge, сравнение с `p.turnLastDir`), не удержание клавиши: один раз спровоцированный разворот доигрывает сам по dt каждый кадр (p.turning=true, p.turnT 0..dur), даже если игрок уже отпустил ввод; facing реально меняется только когда доиграл до конца. Передумать — новое нажатие исходного направления посреди разворота (тоже edge) крутит turnT назад с текущего места, не с нуля; нет 'turn' anim у скина — instant flip как раньше. Пока `p.turning` — прыжок (обычный и wall-jump), block (`p.mountBlocking`), атака (`entities/enemies.js:attack`) и высадка (`tryDismount`) заблокированы, гейты в core/step.js и внутри самих функций. **Speed multiplier** (entities/vehicles.js:mountSpeedMul): раньше редактор читал, но игра игнорировала; теперь применяется как `* lim` на макс скорость в step.js, 1 по дефолту. **Jump multiplier** (entities/vehicles.js:mountJumpMul): 0 отключает прыжок за рулём, `>0` умножает на `p.mv.JUMP`, 1 по дефолту. **Wall-slide multiplier** (entities/vehicles.js:mountAllowsWallSlide): 0 отключает слайд по стене, `>0` разрешает, 1 по дефолту. **Рендер**: герой, сидящий в маунте (p.mount truthy), не рисуется (его бокс скрыт); вместо этого рендер ищет кадры спрайта транспорта (`tryVehicleSprite` с маппингом state/phy на anim: idle/move/jump/fall/land/attack, плюс короткое 0.25s окно на фреймы mount/unmount при посадке/спуске через p.mountAnimT/p.mountAnimKind — чисто визуально, не влияет на физику). Если спрайт не запечён, рисуется фиолетовая коробка-фоллбэк (`drawMountFallback`). Запаркованные (не занятые) транспорты используют anim `idleOff` по умолчанию вместо `idle` (render/sprites.js). При смерти игрока (hp≤0) маунт сбрасывается, runtime.mountSkin=null. **Окно высадки** (core/step.js, начало `step()`): `p.mount` обнуляется сразу в `tryDismount`, но unmount-анимация (`p.mountAnimT`/`mountAnimKind==='unmount'`) ещё доигрывает 0.25с — герой физически уже не за рулём, однако визуально всё ещё транспорт, поэтому весь ввод (движение, прыжок, Act — новая посадка/атака/подбор, ↑/↓) на это время зануляется тем же паттерном, что у `talking` (плюс `p.buf=0`, чтобы не пролез буферизованный до высадки прыжок); полностью восстанавливается кадром, когда `finishDismount` уже отработал.

Оверрайды движения героини (hero-move.js): на уровень можно переопределить узкий набор констант движения из `C` (`RUN`, `ACC`, `FRIC`, `WALK_V`, `CROUCH_V`, `PRONE_V`, `DASH_V`, `SLOPE_ALONG`, `GRAV`, `MAXFALL`, `JUMP`, `CUT`, `COYOTE`, `BUF`, `SLIDE_V`, `WJ_X`, `WJ_Y`, `WJ_LOCK`, `WJ_SAME_X`, `WJ_SAME_Y` — примерно 19 ключей, намеренно исключены `STEP_UP` как геометрический допуск, не "ощущение"), хранятся в `LV.spawn.moveParams` (diff-store как в `editor/params.js`). `buildMoveOverrides()` собирает финальный набор `p.mv`, читая `LV.spawn.moveParams` или fallback на глобальные `C`. Весь player-movement код в `step.js` + `player.js` (+ враги в `entities/doors.js` и `entities/ropes.js` для прыжков/слайдов) читает `p.mv.KEY` вместо `C.KEY` ровно в этих местах, остальные сущности (валуны, пауки, узлы канатов) остаются на глобальных `C.*` без изменений. Редактор: плавающее окно `#edHeroMoveSettings` (как Vehicle/Boulder/Rope) с набором слайдеров из `PARAM_GROUPS`, открывается кнопкой "Movement…" в Object Details для Hero/Start; изменения пишут в `LV.spawn.moveParams` и live-патчат `p.mv` для мгновенной feedback в тестплей.

Ступень +1 тайл: без ↑ — упор в стену; вперёд+↑ — `tryMantle` (анимация climb). Авто-паркура при ходьбе нет. Смена стоек по вводу ждёт `stanceT`. Авто-вставание (`gapCrawl`) — один раз в момент выхода из тоннеля, когда стоя уже влезает; внутри не поднимает. Из лёжа у края: яма больше тайла — вис, иначе скат. Из приседа ход с открытого края — слезание в вис (`tryCrawlEdge` → `tryDescend`). Присед + ход + ↓ — перекат (`rollT`), не лёжа и не слезание. Стоя ↓ без разбега — присед; с разбега (`vx>58`) — перекат как раньше. Из свисания лаз в стойку щели тоже после анимации. У открытого края стоя ↓: присед → лёжа → вис; удержание ↓ (`C.EDGE_HOLD`) — сразу в вис, кроме хода от края (`awayFromEdge`).

Щупальца водорослей (`entities/tendrils.js`, `LV.tendrils: [col, row, kind]` или `[col, row, kind, side]`): корень на твёрдом тайле. `side` 0 пол↑, 1 потолок↓, 2 левая стена→, 3 правая стена← (без поля — пол). kind 0 тянется и жалит (−1 hp); kind 1 обвивает (`p.state==='snare'`), тащит к корню, держит `C.TEND_HOLD` (~2.6 с) и отпускает. Воздух на хвате тикается (`tickSnareAir`); вырваться — палкой, гарпуном или дёрганьем. Убийство палкой/гарпуном — в `stepTendrils` (`probeHarpoons`, цикл импорта через `harpoons.js` нельзя). Рисуются поверх героини (`tendrils()`).

Пауки (`entities/spiders.js`): если потолок над ними пропадает (хрупкий `CRUMB` в `S.gone`) — падают и убегают (`fall`/`flee`, без лута). Паутину на спуске можно порвать палкой или гарпуном — тот же срыв. Нить рисуется чередованием светлого/тёмного, не сплошной верёвкой.

CRUMB (id=2): idle/crack drip и burst осыпания — `emitSand` (`render/sand-fx.js`, `SAND_DEF`); в `gone` тайл не рисуется (без rubble). Placeable `FX Sand` (`fx_sand`) — `entities/emitters.js` (`mkEmitters`/`stepEmitters`/`sampleEmitterPoint`/`packEmitter`); `EMIT_SHAPES` point|square|circle|line; поля `shape`/`shapeSize`/`shapeAngle` (дефолт point/16/0); спавн зерна внутри формы → `emitSand`.

Канаты (`entities/ropes.js`): `LV.ropes` / `S.ropes` — `{id, orient:'v'|'h', ax,ay,bx,by, segs, elasticity, swingForce, length(H), optional damping/wind/climbV/grabR}`; runtime — Verlet `nodes` (`mkRopes`/`mkRopeAt`, `rebuildRope`, `packRope`). Constraint: equality к rest; elast→`eff^2.2`, stretch=eff·0.85 (мягкая пружина, не hard clamp); soft=eff/(eff+0.28); rider load gaussian. В `full` (rider / near player) после каждой итерации constrain незакреплённые ноды выталкиваются из solid-тайлов (`solidAt`, `C.ROPE_COL_EPS`). Райдер: clamp `t` + упор боками/головой (`resolveRopeRiderPose`); спуск на землю/платформу → отцеп. H: `lengthExtra` (0=span); хорда в основном без rider. V: wobble+climbLock; анимы `ropeClimb`/`ropeSwing` (по умолч. ladder/ladderD, facing зеркалит swing). H: bars; ↓ отцеп. `C.ROPE_*`.

Платформы (`entities/plats.js`): `LV.plats` / `S.plats` — `normPlat` / `mkPlatAt` / `packPlat` / `stepPlats`. Параметры: `w,h,v`, путь `x0/x1/y0/y1` + `vert`, `pause0/pause1`, `travel` (`pingpong`|`oneway`), `loop` (`infinite`|`once`), `trigger` (`auto`|`ride`), `onLeave` (`continue`|`return`|`stop`). Палитра `plat_h`/`plat_v` (MARKER); Inspect + гизмо `move`/`platA`/`platB`. Хват края (`tryGrab`): plat-края раньше тайлов (иначе губа клетки под палубой даёт ~T смещение); `facing` = лицом к платформе (`-edgeSide`); `keepAx`/`keepUp` гасят удержанный ход/↑. На палубе `findDescend` только `findDescendPlat`; лаз вверх — `standBox` на палубу (не `bestLand`). Вис+plat в solid → `crush`. В воздухе поза/клип всегда `fall`.

Лифты (`entities/lifts.js`): `LV.lifts` / `S.lifts` — `normLift` / `mkLiftAt` / `packLift` / `syncLiftFloors` / `stepLifts`. Параметры: `w,hh,v,dwell`, `floors[]`, `homeIdx`, `travel`/`loop`, `trigger` (`call`|`auto`|`ride`), `onLeave` (`stay`|`return`). Палитра `lift` (MARKER); Inspect (+/− Floor) + гизмо `move`/`liftFloor`. Call-кнопки в `step.js` только при `trigger==='call'`.

Враги (`entities/enemies.js`): `LV.enemies` / `S.enemies` — `mkEnemies` / `stepEnemies`. Уровневые враги — массив `[x, y, x0, x1, v, kind, loot?, random?, spriteId?, objectKind?, aiCfg?]` (11-й элемент `aiCfg` опциональный, пишется только при отличии от дефолта). Runtime-поля врага: `points` (массив мировых x-координат, ≥2, заменяет x0/x1 которые теперь производные min/max points), `pointPause` (массив пауз в секундах на каждую точку, соответствует каждому элементу points), `canChase` (bool, opt-in, дефолт false), `chaseV` (скорость погони, дефолт v*1.6), `sightFwd` (дальность обнаружения вперёд по направлению движения, дефолт 90px), `hearBack` (дальность слуха назад, дефолт 50px), `jumpH` (высота прыжка через препятствие в px, дефолт 0 — выключено), `aiState` (runtime: 'patrol'|'pause'|'chase'), `ptIdx` / `ptDir` / `pauseT` (state machine). **AI state machine**: `'patrol'` — движение к `points[ptIdx]` с избежанием стен/обрывов; достижение точки → `'pause'` (ждёт `pointPause[ptIdx]`) → переход к следующей (пинг-понг); при `canChase` и видимости игрока (вперёд в пределах `sightFwd` ИЛИ сзади в пределах `hearBack`, проверка высоты ±h/2+4px) → `'chase'` на `chaseV` к центру героя; сброс chase → patrol если враг упёрся в границу патруля (min/max points) или стену/обрыв, либо игрок вышел за `sightFwd`. **Прыжок через препятствие** (`jumpH > 0`): при движении в `patrol` ИЛИ `chase`, если враг упирается в стену (`blocked`), но прыжок высотой `jumpH` расчищает путь (проверка через `rectFree(x, y-jumpH, w, h)`), враг прыгает вместо остановки/разворота; инициируется ветвью рывка через игрока с той же физикой (`vy = -sqrt(2*620*jumpH)`). Пока враг в воздухе (`vy !== 0`), стена не считается препятствием для перехода в pause/сброса chase — это возможно только с земли (`vy === 0`). Если препятствие выше `jumpH`, враг использует старое поведение (pause → разворот патруля / сброс chase в patrol). Остальное (убийство прыжком сверху, контактный урон/щит) не изменилось. **Баг-фикс скорости**: `enemySpeedMult(kind)` / `flierSpeedMult(kind)` экспортированы; `src/core/persist.js` делит `e.v`/`f.v` на множитель при записи (`writeObjects`), чтобы speed не компаундился на каждом save/bake цикле. Данные в `src/core/defaults.js` ручно поправлены для уровней с уже испорченной скоростью. Persist: `enemyAiCfg(e)` пакует `{pts, pause, canChase, chaseV, sightFwd, hearBack, jumpH}` только когда отличается от дефолта (дефолт = 2 точки x0/x1, нет пауз, !canChase И !jumpH). **Редактор**: клик по врагу теперь сразу открывает плавающее окно **Enemy AI** (`src/editor/enemy-settings.js`), без промежуточного попапа лута. Гарпун (`p.gear.harpoon`, рука `p.hand`): в воде — болт как лук (`fireHarpoon`, без подтяга, стрелы подбираются). На суше — крюк (`fireGrapple`): 45° вперёд, при удержании ↑ — строго вверх; длина `C.HARPOON_LEN`, тяга `C.HARPOON_PULL`, отстёгивается за `C.HARPOON_DETACH` и летит по импульсу+гравитации.

Кирка (`p.gear.pickaxe`, рука `p.hand`): отдельный hand-слот (не переиспользует `weapon`), новая ветка в `giveGear`/`wearGear`/`listHand`/`handIndex` (`gear.js`). При экипировке триггер `tryDig(S)` из `tryAction` в `torches.js`. Две анимации: `dig` (замах в стену впереди, горизонтально через `DIG0-2`), `digDown` (замах в пол впереди, по диагонали через `DIGD0-2`). Уменьшает `S.digHp[mapIx]` на 1 за удар; при обнулении тайл прыгает в `S.gone` (перестаёт быть solid и не рисуется). Неразрушаемый тайл (`durability:0`) с каждым ударом генерирует spark-эффект, но не разрушается. Вода — полный отказ без анимации (`isWaterV` проверка). События: `'dighit'` (sparks + осколки), `'digclank'` (только sparks, unbreakable), `'digbreak'` (большое облако пыли + крупные куски).

Contact damage (урон-от-движения, entities/mining.js:stepContactDamage): каждый кадр во время ходьбы/бега, без требования экипированной кирки, гейт как у tryDig (p.state==='normal' && p.onGround). Эффективный урон = max(C.PLAYER_DMG, (p.mount && p.mount.dmg) || 0) — базовый игрока ИЛИ транспорта, за рулём которого он сидит. Работает только если player.facing !== 0 и впереди есть solid-блок (не пусто в rectFree). Таргет — тайл-стена по направлению движения (аналог tryDig, только для стены, не floor-варианта). Списывает S.digHp[k] на dmg × C.CONTACT_DMG_RATE × dt; переиспользует тот же S.digHp и S.gone, что и tryDig — оба источника урона по одному тайлу консистентны (общий счётчик, кто первый доломает). Блоки с durability=0 (обычные тайлы, явно неразрушимые custom-тайлы) не ломаются. Параметры: C.PLAYER_DMG (дефолт 0, редактор Params → Mining/Contact), C.CONTACT_DMG_RATE (дефолт 2 hp/сек на единицу урона).

Смена руки (палка/лук/гарпун/кирка): Q или тап по иконке оружия в HUD (`cycleHand`).

Подбор факела/палки (`tryAction` в `entities/torches.js`) — `tryAction` только ставит `p.pickPend`/`p.pickT`; фактический attach (`t.held`/`p.torch`/`giveGear`) делает `resolvePickup` (вызывается из `step.js` каждый кадр) на нижней точке приседа (доля `PICK_APEX=0.45`, синхронно с `render/poses.js:pickPose`). Бросок факела симметрично: `p.throwT`/`p.throwPend`, сам `dropTorch(S,true)` срабатывает в `resolvePickup` на доле `THROW_REL=0.4` (синхронно с `throwPose`). Ничего не блокирует управление — это оверлей позы поверх `state==='normal'`.

Стойка стоя/присед/лёжа: хитбокс в `setStance` сразу (физика), поза блендится `p.stanceT`/`p.stanceFrom` (`C.STANCE_T`). Следующий шаг по вводу — только когда `stanceT` кончился (удержание ↑ не перескакивает присед). Защитные вызовы (лифт, потолок, перекат) блендинг не запускают.

Падение: `fall > C.SAFE` без переката — `startFallRecover` в присед (`C.FALL_CROUCH_T`) или лёжа если `fall > C.HURT` (`C.FALL_PRONE_T`). Зажатое направление на приземлении — auto-roll (`rollland`); при `fall > C.ROLL_HURT` всё ещё `damage(1, C.ROLL_HURT_T)`. `p.recoverSt` держит стойку, `state==='stun'` блокирует ввод; по таймеру `finishFallRecover` сама встаёт (или в присед, если потолок). Из лёжа хитбокс остаётся `stance===2`, пока играет `getupPose` (`p.gettingUp` / `getupT` = `C.GETUP_T`); `setStance(0)` только в `finishGetup`, когда поза доиграла — иначе корпус висит в воздухе. Иначе ещё `C.STANCE_T` без управления, потом контроль. Урон как раньше. `hp<=0` — `S.dead`, игра на паузе, затемнение и плашка «life capacity reached»; тап/любая клавиша — в меню (больше не `resetPlayer` на чекпоинт). Dev: `9` / `GAME.toggleInvuln()` — полный иммунитет к `damage()` и hard-land knockdown (враги/падение/drown и т.п.).

Взгляд вверх стоя на месте: `p.lookUp` (0..1, плавно) в `step.js`. Тело не меняет позу — поворачивается только сама голова вокруг основания черепа (`render/figure.js:drawHead`, угол `tilt` пробрасывается через `figure()`), коса по-прежнему свисает по своей физике (`wag`/`view.tail`), не завязана на поворот головы. Поворот пикселей головы считается в JS и округляется до целого пикселя (не через `ctx.rotate` — тот даёт субпиксельные прямоугольники и голова «мутнеет», не вписываясь в остальной чёткий пиксель-арт рендер). Камера уже давно приподнимается в этом случае (`wantLook` в `followCam`, `render/camera.js`) — только позы игроку не хватало.

Упор в стену: `p.pushWall` (в `step.js`, ветка `ax !== 0` при блокировке движения) — true только пока держат ввод в стену на земле в стойке; отпустили — сразу `false`, обычная стойка. Поза `WALLPUSH` (`render/hero.js:boxPose`) — ладони на уровне груди, чуть вверх по стене, не вытянуты вперёд.

## Рендер

**Плотность пиксельного буфера** — `RENDER_SCALE` (`src/render/ctx.js`, дефолт 2): множитель плотности backing-store canvas, независим от зума редактора (`viewScale`) и мирового FOV (`VW`/`VH`). Сам мир видится одинаково (те же мировые единицы), но на экран выводится больше физических пикселей — позволяет арту спрайтов/тайлов с повышенным разрешением (`res` в `_meta` кадра, 1–8) выглядеть чётче. Все backing-store канвы (`cv`, `hv`, `lc`) физически размером `VW/VH × RENDER_SCALE` пиксели. Работа с RENDER_SCALE теперь унифицирована через три примитива: `deviceScale()` — возвращает `viewScale * RENDER_SCALE` (физические пиксели канваса на мировую единицу прямо сейчас); `applyWorldTransform()` — устанавливает `ctx.setTransform` с правильным масштабом (7 мест в `loop.js` и 2 в `editor.js`); `makeBakeCanvas(w, h)` — создаёт offscreen canvas размером `w*RENDER_SCALE × h*RENDER_SCALE` с уже установленной трансформацией. Запечённый canvas (`makeBakeCanvas`) блитится обратно `blitBake(can, w, h, dx, dy)` явным src/dest rect — избегает двойного масштабирования. Это унифицирует ранее рассеянные ручные вычисления: `chunkOf`/`stampOf`/`coverCanOf`/`tintScratch` в `tiles.js`, `introCv`/`outroCv` в `hud.js`, `invCv` в `inventory.js`, `wStrip` (water-wave-strip cache) в `tiles.js`. Пиксель-читания в `hero.js:immerseHero` (волны — wobble) и `volumes.js:applyVolumes` (color-grade регионы) теперь используют `deviceScale()` вместо ручного `viewScale * RENDER_SCALE`. `fold.js:foldBlit` теперь источник из `src.width/src.height` (физический размер canvas) вместо переданных логических `pw/ph` — это делает безопасным использование RENDER_SCALE-sized bake-canvas как источника. `lightPass` в `light.js` комбинирует light-буфер обратно на основной холст явным src/dest rect — избегает двойного масштабирования.

**Адаптивный вьюпорт** (только геймплей) — `VW`/`VH` в `ctx.js` теперь `let` вместо const (дефолт 320×180); функция `setViewport(vw, vh)` переназначает их + `BUF_W/H`. Редактор всегда держит фиксированные 320×180 (собственный `ED.zoom` для масштабирования). В игре `resize()` в `loop.js` (`BASE_VW=320`, `BASE_VH=180`, `MAX_STRETCH=1.5`) вычисляет usable аспект-рацио и расширяет `VW` (широкие экраны) или `VH` (портрет/мобила) без letterbox-полос, с потолком ±50% от базового 16:9. Вместо ручного опроса счётчика `viewportRev` кэши теперь регистрируют колбеки через `onViewportChange(fn)` (push-based subscription). `fx.js:fillSky` и `vignette` больше не кэшируют совсем — они дешёвые, пересоздаются каждый вызов. Инвентарь в `inventory.js` регистрирует `onViewportChange(rebuildInvGeometry)`, так что панель обновляет геометрию/canvas при ресайзе окна, даже если была открыта.

Процедурные пиксели (`rc`/`lb` + кэш `fillStyle`), кэш чанков 8×8. Свет — offscreen multiply; мерцание факела — альфа, не радиус. Позы героя — скелетные ключи. Волны воды — полоса на кадр, только на настоящей поверхности (не под камнем внутри воды); `paintWaveSpan` непрерывен по world X. Базовый travel постоянен: `tileGfx[13].shift` (−100…100, дефолт 100 = канон 2.2 вправо; 0 = стоячая база) — без spatially-varying фазы (она рвала гребень). Wave X (дефолт 50) — амплитуда/bob; Splash (дефолт 80) — сила ряби героя (`getTileSplash`). Два слоя ph2/ph3 с разной фазой/скоростью; у FALL гасится только travel (`WAVE_FALL_RIVER`), амплитуды слоёв сохраняются. FALL: `collectFallSources` + `fallExpandAt` (разбег D≈14) + `fallChurnAt` (бурление под ударом). Игрок: enter/exit `splash` → `addWaterRipple`; плюс `stepHeroWaterRipples` (`tiles.js`, таймер `p.rippleT`) — непрерывная рябь при stand/walk/swim в воде; jump/land/hardland/rollland тоже `addWaterRipple` если `inWater||wading` (`loop.js`). После `hero()` — `drawWaterImmersion()`: гребни волны поверх игрока + лёгкий multiply-band. `immerseHero` (`hero.js`): scanline wobble 1–2px ниже waterline у погружённых пикселей; sprite → `tintHeroBand`; stick → `tintHero` клип ниже поверхности. FALL-струи (`paintFallStrands`): фаза по world Y — непрерывны через столбец; два слоя (L2 фаза от `offset`); светлая нить smoothstep ярче снизу → прозрачнее вверх; висячий кончик (пусто под столбцом): `fallColumnTip`/`fallTipKind` + `taper`/`taperLen` — края→точки→пропаж, центр дольше линией, заливка сужается к центру; `paintFallEnds` → `paintFallFoamWave` + `paintFallSpray`; шапка на верхнем FALL; низ — ударная пена/брызги если под низом **любой** тайл (`hit`, не только WATER); пусто = без ударной пены; meta `tileGfx[14]`: `speed` 0–200 дефолт 70, `length`/`wave`/`random`/`offset`/`fade` 0–100 (25/15/35/55/0), L2: `speed2` −100…100 (−8), `length2`/`density2`/`wave2` 0–100 (20/50/20; density→1…8), `foam`/`spray` 0–100 (45/55), `foamSize`/`foamRandom` 0–100 (40/40), `foamSpeed`/`spraySpeed` 0–200 (100/100), `taper` 0–100 (60), `taperLen` 1–12 (6); getters + Details Taper/Taper Len + Foam/Spray suite. Озеро: `LV.water: [[col,row,shade],…]` — `shade` 0 чистая … 1.7 бездна, затемняет тайлы и героя по глубине от поверхности; в редакторе пресеты на кисти «вода». Брызги на верхних тайлах у берега (гребень волны). Пузырьки — разный размер и скорость. Передний план — offscreen по ширине карты. `torchPts` кэшируется на кадр. Камера — `render/camera.js`: `clampCam` + якорь `cam.ax/ay` (`C.CAM_DZ_X/Y`, дефолт 10×8px) — `want` не за игроком напрямую, а за якорем; lead/look на `C.CAM_LEAD*` / `C.CAM_LOOK*`; резина `followCam` (`kk=1-exp(-CAM_FOLLOW*dt)`, дефолт 6.5), `CAM_SNAP` 1px липнет к цели. `pushCamRender` при `C.CAM_SUBPX` (дефолт 1): мир на `#c` буфер 321×181 (`BUF_W/H`, light buffer тоже +1) в `floor(cam+shake)`, доля — CSS `translate` `#c` на `round(frac * viewCss / 320)` внутри overflow:hidden `#view` (шаг экрана, не субпиксельный blit тайлов). HUD/vignette/fade/intro/outro/inventory/pause/dead на втором канве `#h` (320×180, физически VW×VH пиксели с RENDER_SCALE), без translate. Редактор и `CAM_SUBPX=0` — старый `Math.round(cam)`. `clientToGame` — rect `#view`. Ключи в Params → Camera, persist `ledge.dev.C`. `resetCam` на старте уровня обнуляет lead/look. Приземление (`landdust`, `fall>6`) — мягкая пыль у ног, число/разлёт от высоты; удар головой о потолок в прыжке (`bonk` в `moveY`, `vy<-36`) — крошка вниз. Песок/пыль: `emitSand`/`SAND_DEF` (`sand-fx.js`, реэкспорт fx/index) + `landDust`/`bonkDust`; частицы `kind:'dust'` в `drawParts` (альфа, размер, drag).

Персонажи (процедурный рендер) — `src/render/characters.js` — реестр hero-family персонажей (`getCharacter(id)`); каждый персонаж имеет palette / style / headRows / parts / headPivot / partPivots / drawOrder. `src/render/hero-look.js` — данные Hero (палитра, пропорции, форма головы, части тела, извлечены из старых хардкода constans); `src/render/shirley/data.js` — второй полный персонаж "Shirley", авторизованный через внешний инструмент Shirley.html и экспортированный как palette/style/headRows/parts/headPivot/partPivots/drawOrder. `figure()` в `src/render/figure.js` теперь принимает два новых параметра в конце: `charId`, `animId` — разрешает активного персонажа через `getCharacter(charId)` и использует его палитру/стиль/форму головы/части вместо единственного хардкода Hero-look; поддерживает per-character/per-animation `drawOrder` (fallback на старый хардкода порядок слоёв для базового персонажа 'hero' или персонажей без кастома drawOrder). Расширенная поза на основе 11-точечного скелета из `src/render/poses.js`: процедурный рюкзак, 3-сегментный хвост, независимые передние/задние плечи и тазобедренные кости (`upgradePose` в figure.js). `src/render/hero.js` разрешает активного персонажа через `activeHeroId()` (из `src/core/player.js`, управляется `spriteId` spawn-объекта уровня) и передаёт `charId`/`animId` в `figure()`. `src/render/sprite-anchors.js` и `src/render/sprite-bake.js` изменили hero-detection с литеральной проверки `id === 'hero'` на `isHeroSprite(id)` (из `src/core/spriteset.js`), поэтому baked-frame anchor defaults и sprite-baking canvas теперь работают для любого hero-family sprite id, не только буквального 'hero'. `src/render/sprites.js` (`blitEntSprite`) и `src/render/hero.js` (`blitHeroSprite`) используют явный `ctx.drawImage(img, 0, 0, img.naturalWidth, img.naturalHeight, x, y, fw, fh)` вместо нативного размера — PNG-кадр всегда масштабируется в мировые `fw×fh` пиксели независимо от своего фактического разрешения. Отдельного множителя разрешения арта (`res`) больше нет как явной сущности: `tile-edit.js` держит разрешение холста (`bufW`/`bufH`) отдельно от Size (`fw`/`fh` — мировой footprint/якоря/хитбокс, из `_meta`) и берёт его прямо из фактического кадра при загрузке (`loadBuf`). Импорт картинки (`applySpriteImport`) не режет лист и не подгоняет под Size — кадр сохраняется как есть, в своём разрешении; смена Size (`applySpriteSize`) тоже не трогает пиксели кадров. Так земляные тайлы (арт 32×32 на 16×16 клетку) и любой другой спрайт/декоративный объект рисуются каждый в своём разрешении, не обязанном совпадать с footprint.

Кисть скоса красит тайл как обычный (без адаптивного подбора id по форме росчерка). Вертикальный флип (**Y** при рисовании) зеркалит скос: сплошная сторона переходит на другую грань тайла (без Y — низ, с Y — верх). Обе ориентации симметричны и работают как обычный блок независимо от поворота: блокируют AABB по своей гарантированно-сплошной грани (`slopeBlocks` в `map.js`), дают опору сверху на диагональ/плоский верх (`groundYAt`) и останавливают движение вверх о диагональ/плоский низ (`ceilYAt`, событие `'bonk'`). Ledge-grab (`findLedge` в `player.js`) цепляется за скос в любой ориентации по точной аналитической высоте диагонали в колонне руки (`ledgeTopAt` в `map.js`, читает `slopeTop`), а не по гране тайла — иначе рука хваталась за пустой верх квадрата вместо самой диагонали. Залезание (`tryClimbUp`/`tryMantle`/`tryClimbOut`) и слезание (`tryDescend`/`findDescendTile`) со скоса работают как с обычным блоком — `findDescendTile` тоже читает `ledgeTopAt` вместо округления к сетке тайла, а проверка опоры/пропасти под ногами (`solidTile`) дополнена `isSlopeV`, иначе скос на пути к уступу считался пропастью. Посадка после mantle — `bestSlopeLand` (`player.js`): любой уклон, включая 45° (это по-прежнему обычный ходибельный угол, не стена — отдельного "стенового" режима больше нет, пробовали и убрали), сажает по своей диагональной высоте в точке приземления, консервативно по наименее глубокой границе бокса (как `slopeBlocks`) с 1px запаса — иначе то плоское дно бокса зарывается в поднимающийся дальше солид, то сидит впритык к rectFree и следующая же анимация (`land`, доля px другой высоты) рассинхронивает габариты со стойкой. До AABB-шага (`step.js`) высота посадки на склон, на котором уже стоим, тоже берётся по всей ширине бокса (`groundSurfaceUnder`), а не по одной точке в центре стопы (`slopeUnderAt`) — иначе `moveX` не находит STEP_UP (макс. 3px) для края бокса и вместо шага телепортирует на всю ширину тайла. Страховка рассинхрона стойки (`step.js`, «габариты рассинхронились») тоже получила 1px допуск вверх (со сдвигом самого бокса, не только повторной пробой — иначе `setH` пересчитывал bottom по ещё старой высоте и давал двойной скачок по Y, видимый как дребезг даже на плоских тайлах). Присед/лёжа по ↓ (`setStance`) на скосе получили тот же STEP_UP-допуск — разная высота бокса на одной и той же диагонали требует разного запаса, и без допуска смена стойки посреди ровного места на скосе била в rectFree. Лёжа (`PRW`=17 — шире тайла) физически не всегда влезает на крутом 45°-скосе иначе чем у самого высокого края — бокс шире шага диагонали неизбежно захватывает её от подошвы до вершины, это не баг, а геометрия; поэтому лёжа на скосе не разворачивается под угол, а просто недоступна по ↓ из приседа (`slopeUnderAt` под ногами) — на скосе доступны только стойка и присед, как и было предложено (повернуть бокс под уклон — отдельная фича, не делали). Заход на пологий скос с ровного места раньше стопорился ещё до AABB-шага: предохранитель «упор в стену» (`step.js`, `blocked`) проверял только «уже стоим на скосе» (`slopeUnder`), не «скос начинается прямо тут», и отрубал `vx` раньше, чем `moveX` пробовал STEP_UP — чинится проверкой скоса и в клетке перед игроком. Отдельно `footSupported` (порог опоры под ногами) получил тот же +2px запас, что у `groundYAt` — без него при заходе на скос предшаговый snap на долю пикселя не дотягивался до пола, `onGround` на кадр мигал false, и это триггерило неродственное правило «в приседе в воздухе — тянемся выпрямиться» посреди ровной ходьбы, силой возвращая стойку 0. Залезание на крутой скос направлением+вверх работает как на обычный тайл: тот же предохранитель «упор в стену» глушил `blocked` полностью для любой клетки-скоса впереди, из-за чего mantle (`tryMantle` по вводу ↑) для скосов не вызывался вообще — «сырой» упор (`rawBlocked`, без исключения для скоса) теперь отдельно от `blocked` (который по-прежнему глушится для скоса ради гладкой ходьбы по пологому). Mantle пробуется только если сама ходьба не пройдёт даже с STEP_UP-допуском (`canStepUp`, та же проверка, что у `moveX`) — иначе просто зажатая по привычке ↑ при заходе на пологую рампу превращала бы обычный шаг в лишнюю climb-анимацию. Упор+вверх с земли лезет и на стену выше 1 тайла — `tryClimbWall` (`player.js`, `findWallTop`): та же схема, что у `findChestStep`/mantle (скан сплошной колонки вверх от ног), но без потолка «ровно 1 тайл», предел — `C.CLIMB_WALL_TILES` (дефолт 3, Params → Grab/Climb → Climb wall tiles), подобранный так, чтобы это не выходило за то, что и так достижимо обычным прыжком+хватом (`tryGrab`/`findLedge` в воздухе). Первая попытка — переиспользовать `findLedge`/`grabTo`/`tryClimbUp` как при прыжке — не подошла: у `findLedge` узкое окно высоты руки (`TOL_UP/DN`, ±3…6px), рассчитанное на момент пролёта мимо кромки в прыжке, а не на фиксированный рост стоя на месте, поэтому геометрический скан по колонке (как у mantle) надёжнее. Верхний тайл стены может быть скосом — `findWallTop` пробует посадку (`bestSlopeLand`) на каждом ряду снизу вверх и берёт первый, где она реально влезает без наложения на диагональ: педестал под скосом с открытым ближним краем — влезает уже на него (привязка к нижней грани скоса), а не только на пик. Для рядов, где сверху скос, СНАЧАЛА пробуется посадка впритык к грани без обычного отступа `STAND_OFF` вглубь (`edgeLand`) — отступ, рассчитанный на шаг на плоский блок, на скосе сразу толкает бокс в подъём. Даже впритык самое начало диагонали чуть перекрывает низ бокса на пару px — `edgeLand` получил тот же STEP_UP-допуск, что у `setStance`/`moveX` (пробует y, y−1…y−STEP_UP), иначе привязка к нижней грани отказывала бы из-за мелочи. У по-настоящему крутого уклона (45°, «2:1» — 8px+ подъёма на тайл) бокс стойки/приседа физически шире зазора даже с этим допуском — тогда посадка на педестал не влезает ни при каком X, и это ожидаемо уходит на тайл выше через обычный `bestSlopeLand` со сдвигом вглубь (геометрический предел, не баг); у самых пологих («4:1», 4px на тайл) привязка к нижней грани теперь отрабатывает (с точностью до пары px, в пределах STEP_UP). Повторный клик той же кистью по клетке — рандом из `variants` (у stone: `RNDA`/`RNDB`).
