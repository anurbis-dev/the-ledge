# Changelog (unreleased)

- Fix(editor): импорт картинки прямо на голый тайл (без привязанного спрайта, `applyImportFile` не-sprite ветка) всё ещё резал лист по сетке и растягивал одиночную картинку под фиксированный `fw×fh` — тот же баг, что уже правили для спрайтов, просто во второй копии кода. Теперь ведёт себя идентично `applySpriteImport`: картинка сохраняется как есть, без ресайза; `sliceSheet` в этом файле больше не используется (импорт из `tileset.js` убран).
- Refactor(sprites): убран множитель разрешения арта (`res`, `setSpriteRes`, поле "Res") как отдельная сущность — вместо него холст рисования (`tile-edit.js`: `bufW`/`bufH`) теперь просто берёт разрешение из фактического кадра и живёт независимо от Size (`fw`/`fh` — мировой хитбокс/якоря). Импорт картинки (`applySpriteImport`) больше не режет лист на кадры и не подгоняет/масштабирует картинку под текущий Size — кадр сохраняется в точности как импортирован, любого разрешения, а Size не трогается. Смена Size (`applySpriteSize`) тоже больше не трогает пиксели кадров — рендер (`blitEntSprite`/`blitHeroSprite`, уже умели) сам скейлит нативный размер кадра в footprint. Так земляные тайлы (арт 32×32 на клетку 16×16) и любой другой спрайт/декоративный объект могут быть нарисованы в своём разрешении, а не обязаны совпадать с footprint пиксель-в-пиксель.
