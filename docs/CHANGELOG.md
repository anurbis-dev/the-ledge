# Changelog (unreleased)

- Fix(core,render): слезание с края в вис (`tryDescend`, `dir<0`) проигрывало climb-анимацию как залезание — `climbFrameIndex` (`core/player.js`) брал прогресс кадра `cl.p` напрямую (0→4), не глядя на направление, хотя `climbPose` (`render/hero.js`) для спуска уже инвертировал прогресс (`1 - cl.p`). Спрайтовый клип (`heroClip`) и per-frame box-override (`climbFrameBoxWorld`) шли по той же неинвертированной формуле — теперь `climbFrameIndex` сам инвертирует прогресс при `cl.dir<0`, единая логика для box/pose/спрайта.
- Fix(render): кадр прыжка (полёт вверх, `vy<0`) в воздухе не рисовался — `heroClip`/`boxPose` (`render/hero.js`) в состоянии `!onGround` всегда возвращали `fall`/`FALLP`, хотя поза `JUMPP` (`render/poses.js`) существовала, но никогда не импортировалась и не использовалась. Хитбокс уже различал их (`sprite-grab.js:heroBoxAnim`, порог `vy>60`) — арт и бокс расходились. `heroClip`/`boxPose` теперь используют тот же порог `p.vy > 60 ? fall : jump`.
- Fix(app): после поворота экрана (landscape↔portrait) на мобильных оставалась строка адресной строки браузера — `orientationchange` (`app/loop.js`) теперь помимо `resize()` повторно вызывает `requestMobileFS()`, переустанавливая fullscreen, который поворот часто сбрасывает.
- Feat(app,ui): принудительный fullscreen + landscape-lock на мобильных — новый `src/app/fullscreen.js` (isFS/enterFS/exitFS/isMobileTouch/requestMobileFS); `ui/splash.js` вызывает `requestMobileFS()` синхронно в первом user-gesture (тап по сплэшу) на touch-устройствах; `app/loop.js` (кнопка `#bFS`) переиспользует те же хелперы. iOS Safari не поддерживает Fullscreen API/orientation.lock программно — для portrait там (и как общий предохранитель на всех touch-устройствах) добавлен блокирующий CSS-оверлей `#rotate` (`index.html`, `styles.css`, `@media (pointer:coarse) and (orientation:portrait)`), просящий повернуть телефон.

- Feat(core,entities,render): автомобиль (транспорт, vehicle mount) — расширены аним-слоты (turn, block, action1, action2), стойка за рулём гейтится по наличию аним у скина (crouch/prone не доступны без кадров), разворот вместо мгновенного флипа (если есть 'turn' anim), новые множители jumpMul (прыжок) и wallSlideMul (слайд стены), редактор: слайдеры Jump и Wall slide в окне Vehicle. Bug fix: speedMul теперь применяется в игре (раньше редактор читал, но ход игрока его игнорировал).
- Feat(core,render): ↓ за рулём транспорта без 'crouch' anim, но с 'block' — включает `p.mountBlocking` (поза 'block' вместо приседа, стойка/хитбокс героини не трогаются); action1/action2 пока не замаплены ни на один ввод.
- Fix(editor): окно Vehicle-параметров (и Hero Move Settings) не перетаскивалось за шапку/ПКМ и не резайзилось — `bindAllFloats()` (editor/float.js) навешивает drag/resize только на захардкоженный список id, `edVehicleSettings`/`edHeroMoveSettings` в нём не было, хотя разметка и код окна (`ed-float`, `placeFloat`/`raiseFloat`) были такие же, как у Boulder/Rope. Добавлены оба id в список.
- Fix(core): разворот транспорта (`stepMountTurn`) переделан с "играть, пока держат противоположную сторону" на edge-триггер — сама смена желаемого направления один раз запускает scrub, дальше он доигрывает автоматически по dt каждый кадр независимо от того, держит ли игрок клавишу; передумать (нажать исходное направление ещё раз) тоже edge, крутит те же кадры назад с текущего места. Заодно пока `p.turning` — блокируются прыжок (обычный и wall-jump), block, атака (`entities/enemies.js:attack`) и высадка (`tryDismount`), не только ускорение в новую сторону.
- Fix(core): окно высадки (0.25с unmount-анимации после `tryDismount`, пока транспорт ещё виден на экране) не блокировало ввод — `p.mount` уже null, поэтому герой мог тут же побежать/прыгнуть/атаковать/сесть обратно, пока визуально всё ещё стоял на месте транспорта. `core/step.js` теперь зануляет весь ввод на это окно (тем же паттерном, что у `talking`), плюс сбрасывает буфер прыжка.
- Fix(core,editor): персонаж перестал «цепляться» за края выше 1 тайла — `tryClimbWall` (`player.js`) лез с земли направлением+вверх без прыжка на стену любой высоты до `C.CLIMB_WALL_TILES` (3 тайла), подменяя собой настоящий хват прыжком (`tryGrab`→hang→`tryClimbUp`). Теперь с земли без прыжка залезается (vault) только на стену высотой ровно 1 тайл (в т.ч. со скосом сверху с открытым ближним краем) — выше нужен прыжок+хват. `C.CLIMB_WALL_TILES` и его Params-слайдер убраны как более не нужные.
- Fix(core,editor): прыжковый хват (`tryGrab`/`findLedge`) за стену выше 1 тайла на практике почти никогда не срабатывал — при разбеге в стену `moveX` гасит скорость не всегда строго впритык (суб-пиксельный зазор до ~1–2px), а рука (`heroGrabWorld`) тестировала ровно одну колонку без запаса, из-за чего попадала в пустую соседнюю колонку. `findLedge` получил X-допуск `C.TOL_X` (3px, Params → Grab/Climb → Grab tol X, по аналогии с уже существующим `PLAT_GRAB` у платформ) — пробует руку на `0..TOL_X` px вглубь по направлению взгляда, приоритет всё равно у точного касания. Проверено симуляцией прыжка в браузере (`core/step.js:step`) на синтетической стене: хват на стену высотой ровно 3 тайла (максимум, ранее доступный и с земли через `C.CLIMB_WALL_TILES`) заработал, 1–2 тайла по-прежнему просто перепрыгиваются без хвата.
- Fix(render): при висе/лазе за кромку (`state:'hang'|'climb'`, `kind:'ledge'`) точка хвата на спрайте героини уезжала на `2×fx` (≈6px) при facing<0 — `blitHeroSprite`/`spriteLocalScreen` (`render/hero.js`) зеркалят арт вокруг `wx+fx` (визуальный центр от края физбокса, нужно только когда `wx`=реальный бокс, как при беге), а для виса/лаза `wx` — это мировая точка хвата (`p.hang.cx`/`p.climb.cx`), и origin-кадра должен садиться ровно в неё при любом facing. Обе функции получили опциональный параметр `fxOverride`; для pinned-рендера (вис/лаз) теперь передаётся `fx=0`, при котором зеркало проходит ровно через `wx`. Бага не зависела от анимации/кадра — фикс на уровне рендер-функций, действует сразу на весь вис/лаз, не на одну позу.
- Feat(core,editor): per-frame **box override** для объектных якорей (`object-anchors.js`: `getFrameBox`/`setFrameBox`/`clearFrameBox`, `rec.boxFrames[]` — по образцу уже существовавшего per-frame `weapon`) — позиция+размер хитбокса конкретного кадра, независимо от `origin` (у обычного анимного box позиция всегда = origin). Колижен во время подъёма по кромке (`updateClimb`, `player.js`, kind `'ledge'`) раньше всегда ехал по прямой `from→to` за время анимации, не глядя на то, что в этот момент реально рисует спрайт (`climbPose`/per-frame `origin`), из-за чего на затяжном pull-up бокс мог визуально разъезжаться с позой. Теперь если у текущего кадра climb (`climbFrameIndex` — общая с `heroClip`, render/hero.js, формула выбора кадра по прогрессу) есть override, `updateClimb` ставит бокс прямо по нему (мировая проекция — тот же pinned fx=0-принцип, что у фикса рендера виса/лаза чуть выше); без override — прежний лерп, поведение не меняется. Редактор: Object Details → **Frame box** (чекбокс + Frame pos/Frame size, под обычным Box), голубой контур на канве вместо обычного красного, когда override активен для текущего кадра; старый драг-ресайз хитбокса мышью по-прежнему правит только Origin+анимный Box.
